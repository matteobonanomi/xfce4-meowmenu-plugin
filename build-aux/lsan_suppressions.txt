# LeakSanitizer suppressions for the MeowMenu CI `sanitizers` job.
#
# Scoping rules (see spec.md Edge Cases §266, data-model.md §170):
#   - Suppressions MUST be per-function or per-symbol.
#   - Whole-file or whole-library production suppressions are FORBIDDEN.
#   - Every suppression MUST cite the upstream bug it tracks and the date
#     it was added. Stale entries without a tracking link are removed at
#     the next audit.
#
# Format: one `leak:<symbol-or-regex>` rule per line.
#
# FcInit — fontconfig global state is intentionally never freed at process
# exit (it is a per-process singleton). LSan triggers when Pango initialises
# a font backend in a GLib thread spawned by gtk_init_check(). No code
# defect; suppressed to keep sanitizer signal clean.
# Upstream acknowledgement: https://gitlab.freedesktop.org/fontconfig/fontconfig/-/issues/78
# Added: 2026-05-28
leak:FcInit

# FcValueSave — fontconfig retains copied pattern values in its process-wide
# configuration while GTK/Pango construct font layouts. LSan reports those
# values when a short-lived GTK test exits, although the allocations originate
# entirely in the fontconfig/Pango stack.
# Upstream acknowledgement: fontconfig issue 78
#   https://gitlab.freedesktop.org/fontconfig/fontconfig/-/issues/78
# Added: 2026-08-20
leak:FcValueSave
leak:FcConfigSetDefaultSubstitute
leak:FcFontSetList
leak:FcFontRenderPrepare
leak:FcFontSetMatch
leak:FcPatternBuild

# pango_layout_get_size — some distro builds strip the internal fontconfig
# frames that lead to the same process-wide font-pattern cache. Keep the
# suppression at Pango's fontconfig-backed layout boundary rather than using
# a library-wide rule.
# Upstream acknowledgement: fontconfig issue 78
#   https://gitlab.freedesktop.org/fontconfig/fontconfig/-/issues/78
# Added: 2026-08-20
leak:pango_layout_get_size

# gtk_widget_get_preferred_height — the same cache allocations can pass
# through GTK's preferred-size helper without a symbolized Pango frame on
# stripped distro libraries. This remains scoped to the GTK boundary.
# Upstream acknowledgement: fontconfig issue 78
#   https://gitlab.freedesktop.org/fontconfig/fontconfig/-/issues/78
# Added: 2026-08-20
leak:gtk_widget_get_preferred_height

# gtk_cell_renderer_get_preferred_width — short-lived GtkTreeView tests reach
# the same fontconfig pattern cache while measuring text renderers. Ubuntu's
# stripped fontconfig library leaves the allocation leaf symbolized only at
# this GTK request boundary, so the lower-level rules above cannot match it.
# Upstream acknowledgement: fontconfig issue 78
#   https://gitlab.freedesktop.org/fontconfig/fontconfig/-/issues/78
# Added: 2026-09-01
leak:gtk_cell_renderer_get_preferred_width

# atspi_get_a11y_bus — at-spi2 caches a single AT-SPI bus connection for the
# whole process and intentionally never tears it down (a per-process
# singleton). gtk_init_check() reaches it through the accessibility-bridge
# init (atk_bridge_adaptor_init -> atspi_get_a11y_bus); libdbus keeps the
# connection's internal read buffer alive, which LSan reports as a leak once
# a real display lets the bridge initialise under the virtual-display CI run.
# No code defect and no test exercises accessibility; suppressed per-symbol to
# keep the sanitizer signal clean, mirroring the FcInit singleton above.
# Upstream design (the connection is a cached, never-freed singleton):
#   https://docs.gtk.org/atspi2/func.get_a11y_bus.html
#   https://wiki.linuxfoundation.org/accessibility/atk/at-spi/at-spi_on_d-bus
# Added: 2026-06-17
leak:atspi_get_a11y_bus
